# Development security boundary

Do not expose this demo on a public interface. All synthetic identities can be selected without passwords. An explicit `ORBIT_DEMO_MODE=1` is required; production startup is deliberately blocked. Only loopback/test hosts are allowed. Production needs a mature OIDC provider, TLS cookies, managed secrets, durable jobs, resource/retention limits, recovery and independent review before onboarding customer information.

Server-side membership resolves tenant context. Every project operation checks current project grants; credential and proposal identifiers are tenant-scoped. Membership/role changes take effect on existing sessions. Database composite keys prevent project/tenant relationship mismatches. No frontend hiding is treated as authorisation.

Synthetic comparisons/handovers never execute network requests. Version 0.3 adds separate owner-only read-test profiles with disabled-by-default live GETs; see READ_CONNECTIONS.md for the explicit opt-in and host/resource/credential controls. Anyone using the local demo can select its owner identity: this is a single trusted local tester arrangement, not production user authentication. The original synthetic routes never execute vendor writes; the dedicated v0.9 pilot and v0.10 UAT exception are described below. Credentials are encrypted locally and excluded from responses, validation errors and audit details. Resource lists are transient; only sanitised read-result summaries persist. User directories, real documents/model binaries and production secrets are not imported.

Approval requests are immutable in this foundation and use a digest of the exact structured preview. The approving actor differs from the requester. Tenant/project permission, digest and pending state are checked at approval time, with an atomic update. Approval expiry, cancellation and execution preconditions must be implemented before any executable approval is introduced.

Tests cover cross-tenant/API access, database relationships, roles, project and membership revocation, session expiration/logout, cross-origin mutation, untrusted host, credential redaction/encryption and approval scoping/replay/self-approval. This is evidence for the bounded synthetic slice, not a penetration-test or production security claim.

Version 0.4 adds local confidential APS app credentials, one-use PKCE/state consent bound to browser/session/project/connection, a fixed loopback callback, token exchange/explicit renewal and current-discovery-bound selection. Callback query strings are redacted in Uvicorn access logs. OAuth tokens/app secrets remain encrypted and are never returned to the browser. Hub/project/folder names/IDs are cached locally for up to 10 minutes of validity, purged during subsequent discovery/credential changes, and not imported into document registers. See AUTODESK_AND_REDEYE_SETUP.md for local-only limits and unverified live prerequisites.

## Connection preparation records

Preparation routes enforce current session role and project grants. Owners create/update and run the offline Meridian fixture; all authorised project roles may read/export plans. Cross-tenant IDs are unavailable. Optimistic revisions reject stale updates. Provider changes require a separate plan; environment, scope, authentication or network changes clear prior checklist results. Audit records contain plan IDs, not note contents.

These records are non-secret configuration visible to project readers. URL references must use HTTPS and contain no credentials/query/fragment. They are never resolved, fetched or added to live allowlists. This validation does not make the URL a permitted live destination. No Meridian credential store, private-network probe, Windows identity delegation, VPN or remote worker is implemented. Hand-authored Explorer fixtures neither verify access nor update manual test results. Manual results are not approval authorisation or production acceptance.

## Public bSDD references

The bSDD adapter calls only the fixed HTTPS public API with versioned paths and encoded query values. User-provided identifier URIs are never outbound destinations. No credentials or customer document contents are forwarded. Responses have timeout/byte/shape limits; redirects are refused. A bounded five-minute metadata cache contains only anonymous public responses. Viewing saved settings does not make external requests. Owner privileges and project access are required for lookups/saves and rechecked after network work. Project readers can view the local reference schema. Server-sourced property snapshots prevent clients submitting forged definitions, and revision checks prevent silent lost updates. Failure preserves saved settings; clearing the selection is local. This metadata reference is not a compliance engine or an approval to write to vendors.

## Local parameter import execution

Parameter imports bind the exact project bSDD snapshot, destination connection/generation, selected document revisions and existing field/value state to a digest and 24-hour expiry. Approval requires a different actor; execution rechecks the approver's current role/grant and snapshots. Synthetic execution holds a SQLite write transaction, verifies read-back and rolls back all changes on mismatch. Completed replay returns the prior receipt. Cancellation and conflict/type/unit/required-value blockers prevent execution. The general parameter executor does not route real read-test/preparation IDs to an HTTP writer. A separate restricted RedEye pilot was added in v0.9 as described below.

Per-connection field/value foreign keys and tenant/project checks prevent cross-destination writes. Existing values are preserved unless the reviewed request explicitly permits overwrite. No implicit deletion or core document-column mutation occurs. Parameter values and review packages are project data available to project readers; audit details contain job IDs rather than copied values. The demo identity picker remains unsuitable for production access or real separation-of-duties guarantees.

## Additional metadata connections

Additional profiles require current owner/project access, explicit saved test/vendor confirmation, live-read opt-in and an operator-approved exact HTTPS origin. Base URLs forbid embedded credentials, query/fragment, path traversal and loopback/link-local literals. Relative collection paths and object JSON pointers do not execute code. Reserved credential headers/query parameters are rejected. Encrypted credentials are never returned; edits/replacement clear discovery and invalidate generation-bound results. External reads recheck identity, project access and generation before returning/storing their bounded summaries. Provider error bodies are not relayed.

Windows integrated authentication is restricted to the Meridian Explorer adapter, an available Windows executor/library and the same read gates. It uses current-process credentials with delegation off, TLS verification on and redirects off. There is no browser impersonation, stored Windows password, VPN installation or remote worker. The SSPI route preserves normal administrator-configured requests CA/proxy settings. Production startup and identity limitations remain unchanged.

Desired-write flags and manual field mappings cannot grant write capability. New destinations remain blocked in the parameter executor, including Procore proposals compiled from documented schemas. No arbitrary remote write endpoint or native import runner is exposed. Native inventory reads do not establish semantic bSDD binding, complete-project coverage or write permission.

## Isolated RedEye live-value pilot

The dedicated pilot requires a saved confirmed RedEye connection, existing encrypted key, enabled reads, project bSDD snapshot, one matching visible revision, modifiable state, explicit disposable/single-current-approved/no-concurrent-writer and payload/type/unit evidence. A real POST requires a session-bound browser grant in v0.10 UAT, or the legacy separate process flag plus exact connection UUID/host/artefact target. A separate current approver, fresh unchanged snapshots, short expiry and typed exact target confirmation are rechecked before execution. Unverified profile URLs and malformed target environment values are redacted from pilot context; credential-like test/evidence values are rejected before storage.

A durable connection/artefact attempt slot is committed before POST. Crashes, timeouts, new previews and duplicate requests cannot cause another POST to that target. The bounded POST/read-back phase holds a local DB write transaction to prevent concurrent local configuration changes. Read-back compares all returned prior metadata values plus the one proposed value and stable identity/revision/content guards. HTTP acknowledgement and observed read-back state are recorded separately. Uncertain results persist for GET-only rechecks; no automatic rollback/delete/retry exists.

The API's current-versus-approved and concurrency limitations are not solved by client-side checks. The pilot is therefore restricted to operator-confirmed disposable isolated targets, not production data or a general integration writer. Full metadata is a project-scoped test snapshot visible to permitted project readers; audit records contain test IDs rather than copied values. The local identity picker does not establish production authentication or real human separation. Run-ORBIT.cmd clears legacy write flags and starts browser UAT; the advanced read launcher clears write and UAT flags. The advanced write launcher restores prior process environment on exit.

## Local browser UAT (v0.10)

Run-ORBIT.cmd explicitly starts local UAT with live reads available for configured approved hosts. It clears legacy pilot write flags. UAT does not grant general writes: an owner must enable one separately approved, unexpired preview in the browser, then supply its exact WRITE confirmation. The in-memory grant binds the session cookie hash, exact preview/digest, connection generation and host/artefact; only one grant is active per session. It lasts at most 10 minutes, is consumed before POST and never survives a server restart. Session rotation/sign-out makes it unusable. Disabling it sends no vendor request. All existing source, role, project, approval, fresh-destination and durable no-replay controls still apply. The older launchers clear UAT mode and retain their original advanced gates. These synthetic local identities remain unsuitable for a shared or remotely exposed deployment.
